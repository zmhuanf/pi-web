=====================================================
  pi-web 本地定制开发规范（避免与远端合并冲突）
=====================================================
适用范围：本仓库（zmhuanf/pi-web）相对上游 agegr/pi-web 的
本地定制。所有改动 AI 或人工修改前必须先读本文档。

-----------------------------------------------------
一、核心原则
-----------------------------------------------------
1. 本仓库 = 上游 agegr/pi-web + 本地定制。
   上游会持续更新，每次合并都可能与本地定制冲突。
2. 一切改法的唯一目标：合并冲突尽可能少。
3. 判定标准：git diff <上游> 的行数越少越好，
   尤其是「修改上游已有代码」的行数。

-----------------------------------------------------
二、代码放置规范（最重要）
-----------------------------------------------------
本地定制代码必须放进以下目录，禁止散落到上游文件：

    lib/zmhuanf/          服务端逻辑（估算、常量、工具函数）
    components/zmhuanf/   前端组件与 hooks
    bin/zmhuanf/          启动脚本包装

现有文件：
    lib/zmhuanf/context-usage.ts        老对话用量估算
    lib/zmhuanf/scroll-anchor.ts        二次布局后贴底 + 锚点撑高保留
    lib/zmhuanf/thinking-inline.ts      最后一条思考内联判定
    lib/zmhuanf/ssh-session.ts          SSH 模式判定
    components/zmhuanf/FollowButton.tsx 顶部栏跟随按钮
    bin/zmhuanf/ssh-launcher.js         start 包装

新增定制时：
    - 逻辑、组件、hook 一律放 zmhuanf/ 目录
    - 上游文件里只允许留「桥接」：一行 import + 一处调用/透传
    - 上游文件是零冲突的新增路径，改它们=主动制造冲突

-----------------------------------------------------
三、修改上游文件的红线
-----------------------------------------------------
禁止：
    1. 删除或重构上游已有代码（只许增，不许减）
    2. 修改上游的测试文件（*.test.mjs）
    3. 为让测试变绿而迁就实现
    4. 把本地常量硬编码在上游文件里（必须放进 lib/zmhuanf/ 并单独引用）

允许的最小改动（按优先级）：
    - import 一行
    - 函数体内加 1-2 行桥接调用
    - 组件 props 加一个可选参数并透传（尽量用 hook/组件吸收逻辑）

注意：
    - 测试失败不代表功能坏，上游基底本身就带失败用例
      （useAgentSession 4 个、MessageView 环境问题），不要为了
      修测试去动实现或改断言
    - 每次改完自查：git diff 上游 <文件>，确认没有多余删除

五、本地定制功能清单（改坏前先确认需求）
-----------------------------------------------------
（本节仅列出本地独有的定制；默认工具预设已交回上游，见第八节）
1. 右上角用量显示「已用 / 上限」格式（AppShell）
2. 老对话也有用量信息（context-usage.ts + state 路由）
3. 跟随按钮（FollowButton + AppShell/ChatWindow/useAgentSession 桥接）
4. 思考防闪烁：最后一条思考内联（thinking-inline.ts）+
   流式 paint 前同步 + 折叠二次布局贴底（scroll-anchor）
5. 编辑工具默认展开（跟随上游思考展开设置）
6. 默认端口 30142 + Windows build 修复
7. SSH 远程模式：npm run start -- --ssh user@host[:/remote/path|:<port>] [--pass 密码]；
   启动包装摘参注入 PI_WEB_SSH / PI_WEB_SSH_PASSWORD，~/.pi/agent/extensions/ssh.ts
   在 session_start 读取实现 read/write/edit/bash 远程化（冒号后纯数字视为端口
   （非 / 开头），密码认证走 plink -pw（sshpass/askpass 在无 tty 下不可用），
   首次连接自动提取 hostkey 指纹缓存，改扩展时注意保持 pi CLI 兼容）
8. 最后一轮处理详情（思考+工具调用）默认展开：本次打开会话期间出现过实时输出
   才展开，重新打开历史会话仍折叠（ChatWindow tailWasActiveRef + liveTailActive +
   ProcessDetailsGroup 的 defaultExpanded 条件）

-----------------------------------------------------
六、合并上游的固定流程
-----------------------------------------------------
1. 小步合并：频繁合并上游，不要攒大量改动后一次性合并
2. 合并前先读第四节清单，知道哪些文件会撞
3. 冲突解决原则：zmhuanf/ 目录永远全选本地；上游文件的冲突逐 hunk 看，
   本地桥接尽量保留，上游新逻辑优先，桥接行重新放回
   （.git/config 已开 rerere.enabled=true，重复冲突自动套用上次解法）
4. git fetch https://github.com/agegr/pi-web.git main:agegr-main
5. git switch main 然后 git merge --no-ff agegr-main -m "Merge branch 'agegr-main'"
6. 上游动了 package.json 依赖才 npm install --include=dev（见第七节）
7. node_modules/.bin/tsc --noEmit；测试允许不全绿，不为修测试改实现
8. git diff --stat <上游 tag> 对照第四节 21 文件清单
9. git push origin main（普通 push；--force 仅限明确要求时）
10. 不要 force 覆盖 origin/agegr-main：它保存着 2026-08 的 16 个旧定制提交
    （自研滚动/折叠/显示优化，作者 yefengfeng），与本地 agegr-main
    （纯上游快照分支）不是同一条线。本地 agegr-main 只用来 fetch 上游 main，
    不推送、不 checkout

-----------------------------------------------------
七、依赖安装红线（AI 别再弄坏本地环境）
-----------------------------------------------------
1. 本机终端默认 NODE_ENV=production。
   npm install 在此环境下会跳过全部 devDependencies
   （react-markdown、tailwindcss、typescript 等），
   表现为 tsc 报 Cannot find module react-markdown 之类。
2. 确需安装/恢复依赖时，只允许这一条命令：
       npm install --include=dev
   或用一次性环境变量：NODE_ENV=development npm install
   禁止只跑裸 npm install 后就宣称环境已恢复。
3. 合并上游与依赖无关时，禁止顺手执行 npm install /
   npm ci / 清理 node_modules。依赖环境只归本地人工维护。
4. node_modules 缺包时先问人工，不要自作主张重装整个
   依赖树。Windows 下 npm 清理遇 EPERM 会留下半删目录，
   进一步破坏 node_modules。

-----------------------------------------------------
八、上游已移除的本地定制与环境前提
-----------------------------------------------------
1. 默认工具预设：本地不再有 DEFAULT_TOOL_PRESET
   （lib/zmhuanf/preferences.ts 已删），沿用上游 configured
   （未显式选择就跟随 settings.json 的 defaultTools）。
   默认 full 由 ~/.pi/agent/settings.json 提供：
       defaultTools = ["read","powershell","edit","write","grep","find","ls"]
   新机器要重配这条，否则新会话只有四个工具。
2. useAgentSession 里上游已删掉本地 thinkingLevel state，勿再恢复；
   state 初值/loadContext/loadTools 用上游写法，别再加「强制对齐后端」
   的逻辑（那会把用户选择弹回去）。
3. MessageView 工具卡：本地默认展开只做初值
   useState(defaultExpanded || isToolCallExpanded(id))，
   上游 toggleExpanded 持久化逻辑整体保留。
4. package-lock.json 走 npmmirror 源，几个 devDeps 版本范围高于上游
   （@types/react、@types/react-dom、mammoth、typescript），属本地既存，
   改前先问人工。
